# 通用项目模板

> 适用于所有新项目的基础规则和文件结构模板。每个新项目开始时复制此目录并按实际情况填充。

## .trae/rules/ 目录结构

```
.trae/rules/
├── project_rules.md          # 项目长期规则
├── project_framework.md      # 项目框架描述
├── todolist.md               # 待办事项
├── project_iteration_log.md  # 迭代记录
└── universal_template.md     # 本文件（通用模板）
```

## project_rules.md 通用规则模板

```markdown
# 项目长期规则

> 通用原则（规则先行、文档同步、渐进迭代、兼容优先、简洁高效、真人验证、及时提交、移动优先、隐私安全、文件有序、防回退、部署告知、方案归档、规则不重不漏）见 universal_template.md"跨项目通用原则"，此处仅记录本项目特有规则。

## 项目特有规则
- （按项目填写，只记录本项目独有的规则，不与通用原则重复）

## 防止版本错乱/回退规则
- 禁止整文件重写，必须使用局部搜索替换
- 改动前先确认现有代码状态
- 保持历史修复的完整性
- 小步提交，每个独立修复单独 git commit
- 修复前先查 git log

## 推送部署与测试规则
- 推送部署必须确认成功并告知用户
- 推送后教用户线上测试方法
- 推送后给运行总结
- 优化方案写入 todolist 并实时更新进度
```

## 跨项目通用原则

1. **规则先行**：每个项目必须有 .trae/rules/ 目录，开工前先读规则。
2. **文档同步**：每次改动前后都要更新规则文件，保持文档与代码一致。
3. **渐进迭代**：先保证功能正确，再优化体验，最后考虑重构。
4. **兼容优先**：新代码不能破坏已有功能，先兼容后优化。
5. **简洁高效**：代码保持简洁，复用已有能力，不重复造轮子。
6. **真人验证**：每次改动后做真人模拟测试，覆盖实际操作路径。
7. **及时提交**：验证通过后及时 git commit + push，不积压改动。
8. **移动优先**：如项目涉及移动端，任何调整都要兼容窄屏、触控和安全区。
9. **隐私安全**：账号密码、API Key 等敏感信息不得写入代码、配置文件或日志，必须加密存储或使用环境变量。
10. **文件有序**：代码文件放入已有目录的合理位置，不随意在根目录创建新文件；新文件必须符合项目目录结构约定。
11. **防回退**：已完成的优化和拆分不得被后续修改还原，修改文件前必须确认现有代码状态。
12. **部署告知**：推送部署成功后必须告知用户，给测试指引和运行总结。
13. **方案归档**：优化方案必须写入 todolist.md 并实时更新进度，避免后续遗忘。
14. **规则不重不漏**：项目规则和通用规则之间不重复不遗漏，通用规则更新后同步更新记忆。
